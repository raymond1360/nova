# Nova v0.1.0 交互设计说明

> 生效版本：Nova v0.1.0（首个公开测试目标 v0.1.0-beta.1）；决策整合版，2026-10-20 09:53 北京时间。
> 本轮已确认决策优先于旧版冲突内容。本文与 [UI/UX 设计说明](NOVA_V0.1.0_UI_UX_DESIGN10200953.md) 为当前设计依据；旧文件保留归档，不再作为冲突规则的执行依据。
> `Nova 原型.dc.html` 尚未同步本轮决策，只作交互与视觉参考，不能证明真实功能已具备。本文描述目标行为；第 15 节区分代码现状与待实现项。
> Nova 项目分工：Codex 开发，Claude Code 独立审核。产品内部：用户选择单个执行 AI，Nova 独立事实验证，不要求第二个 AI。

## 1. 交互原则与范围

进入项目后使用一个界面、一条对话流，用户用日常语言提出要求，Nova 整理确认、展示实际工作与证据。按钮操作形成可追溯记录；输入框全阶段可用，但输入不等于授权执行或改变已冻结范围。

每轮必须确认范围；执行中新增要求进入下一轮。只有 Nova 验证条件满足、用户实际查看并明确确认，后端验收门禁通过后，才能显示“本轮完成”。AI 自述、进程正常退出、打开预览均不能单独证明完成。

新版核心首包覆盖项目选择、需求对话与确认、真实工作状态及持续反馈、受阻提示、结果查看、用户完工确认。附件内容解析、智能排障、统计另列工作包。软件安装、自动排障代办、任意项目运行不因界面迁移而获得授权或纳入本包。首次引导、GitHub 导入、新建产品仍按一期计划推进。

## 2. 界面区域与开合

| 区域 | 默认与尺寸 | 行为 |
|---|---|---|
| 左侧项目栏 | 展开 230px，收起 48px | 项目、当前轮、历史任务；把手显示项目色块与项目数 |
| 中间对话流 | 常驻，自适应，最小 480px | 对话、需求确认卡、工作卡、验证、结果与验收 |
| 右侧详情抽屉 | 默认收起，展开 286px，收起 48px | 已确认决定、下一轮、证据与脱敏技术详情；把手用文字状态，不用静态进度环 |

不足以同时展开两侧栏时，打开抽屉自动收起左栏；关闭后恢复原左栏状态。按项目记住开合偏好。不打开抽屉也能走完主流程。

窗口最小 1024×700 为目标设计值，正式窗口配置与缩放兼容待迁移验证。各区内部滚动，输入框贴底可见。

## 3. 对话消息、记录与防重复

| 类型 | 更新方式 | 约束 |
|---|---|---|
| 用户文本、Nova 回复 | 保留历史 | 不用新回复静默改写已确认要求 |
| 动态状态 | 原位更新当前展示 | 实际事件与结果仍保留在时间线，不能覆盖掉错误证据 |
| 需求确认卡 | 开始前可更新版本 | 每轮保留确认记录、确认版本、范围和完成标准 |
| 工作与验证卡 | 按实际事件更新 | 计时更新不制造新动作或验证结果 |
| 建议与操作按钮 | 使用后锁定 | 历史按钮不可重复触发执行，标注已处理或已失效 |
| 日期分隔 | 跨天插入 | 恢复前先核对后端记录 |

前端禁用按钮只防误点；后端仍须校验任务、轮次、确认版本和动作状态，使用既有 Action Ledger、attempt/CAS 与幂等门禁防并发点击、重复请求及恢复重放。确认版本过期须返回当前卡片，不能执行旧范围。新版卡片与这些门禁的绑定待实现。

距底 ≤80px 时新消息平滑贴底；上翻时不抢滚动，出现“回到最新消息”。用户发送后到底；卡片计时更新不滚动。

## 4. 固定输入框与附件边界

Enter 发送，Shift+Enter 换行，输入法组字中的 Enter 只确认文字。自动增高至 6 行后内部滚动。空输入不可发送；回复中和执行中仍可输入。技术问题用普通语言回答，不展示内部思维链。

附件选择、拖放、移除可作为后续交互规范保留；图片、PDF、Word、表格、文本的内容解析属于另包，未接入时须明确“文件内容尚未读取”，不可声称理解附件或凭文件名生成事实结论。原型的 1.2 秒上传完成属于模拟。可执行文件与压缩包拒收；真实大小上限、解析策略、上传取消和错误重试待该包确定。首包不得提供看似可解析却无提示的入口。

## 5. 对话确认范围

信息明确时，直接在同一对话流生成需求确认卡，无需用户重新填写技术表单。存在影响实施的歧义时，只问必要问题；不设固定追问次数上限以迫使猜测。关键歧义未解除时保持待确认，不开始执行。

卡片以普通语言说明四项：改哪里、改什么、哪些内容保持原样、怎样判断完成。主操作为“开始修改”，辅助操作为“我再补充一下”。执行 AI 可作为次级信息，不出现强制双 AI 配对。

示例：用户说“按钮太小，改大一点，换成绿色。”在上下文已明确为首页开始按钮时，卡片为：

> 放大首页的开始按钮并改为绿色；按钮文字、点击功能及其他页面保持原样。完成后请查看是否清楚、方便点击。
>
> 操作：开始修改／我再补充一下。

若上下文无法识别哪个按钮，先询问位置。开始前补充要求并入本轮，更新卡片；用户确认后冻结执行范围。确认与启动可组合为“开始修改”的一次意图，后端须确保确认记录生效后才启动且只启动一次，不能因 UI 合并而跳过门禁。

执行中新增需求默认记录为下一轮，告知用户且不扩大当前范围。验收时提出调整也生成新一轮确认卡，保留上一轮未通过或待验收的真实结果；新轮须再次确认，不自动启动。简单改动同样遵守此规则。

必要用户动作包括范围确认、影响结果的选择、处理授权或环境问题、查看效果与完工确认。顺畅路径可为开始修改→打开结果→我已查看，确认本轮完成；不以固定点击数压缩必要确认。

## 6. 卡片规格

通用结构：标题与文字状态→内容行→真实动态信息→普通说明→默认折叠的脱敏技术详情→主／辅助操作。图标用通过、提醒、活动、普通四态，状态不只靠颜色表达。局部检查通过只标该项通过，不能将整轮提前涂成完成。

| 卡片 | 主要内容 | 操作与后续 |
|---|---|---|
| 需求确认 | 位置、变更、保持原样、完成标准、确认版本 | 开始修改／我再补充一下 |
| 工作 | 实际阶段、实际已用时间、最近真实动作及其时间、数据更新时间、执行状态可信度 | 技术详情；下一轮需求数有实际记录才显示 |
| 验证中 | Nova 正在核对的事实与证据来源 | 自动更新，不把 AI 自检当独立验证 |
| 可安全修复 | 本轮范围内的问题、影响、将交回同一 AI；标注“自动修复 1/1” | 仅符合第 7 节时自动进入一次修复 |
| 修复后仍未通过 | 未解决问题、已改内容及保留情况、下一步建议 | 查看结果／补充下一轮要求；停止自动返修 |
| 需要处理 | 环境、登录授权、启动、连接或执行受阻；说明影响与下一步 | 只给实际支持的检查或处理入口 |
| 验证通过待查看 | 实际通过项、未检查项及限制 | 打开修改后的产品；不写本轮完成 |
| 等待用户确认 | 查看结果、Nova 验证结论、需要留意 | 我已查看，确认本轮完成／还需要调整 |
| 项目记录 | 后端已确认完成的本轮结果，下一轮草稿 | 历史操作锁定，下一轮须另行确认 |

没有固定三项任务或固定“3/3 通过”。验证项来自本轮确认标准，不能为了卡片布局伪造项目。

## 7. 状态机与一次自动修复

```text
项目选择 → 需求整理／必要澄清 → 待确认
待确认 ─补充→ 更新同轮确认卡
待确认 ─开始修改，确认冻结且启动门禁通过→ 工作中 → Nova事实验证
事实验证 ─通过→ 等待查看 → 成功打开预览 → 等待用户明确确认
等待用户明确确认 ─验证门禁满足且用户已查看并确认→ 本轮完成
事实验证 ─本轮范围内可安全修复，尚未使用修复机会→ 同一AI自动修复1/1 → 重新验证
重新验证 ─通过→ 等待查看
重新验证 ─仍未通过→ 未完成，停止自动返修
任一执行阶段 ─环境／授权／启动／受阻等→ 需要处理
连接中断／重启 → 核对任务、动作与证据 → 按实际停点续接或需要处理
等待用户确认 ─提出调整→ 新轮需求整理 → 新轮确认卡（不自动执行）
```

首次开发及同次调用内自检不计自动返修。Nova 事实验证发现属于本轮范围且可安全修复的代码问题后，最多交回同一个执行 AI 自动修复一轮。这一轮可修改多个相关文件、处理多个相关问题，并非一行或一个文件。

修复后重新验证；仍未通过即停止，显示未解决问题、修改保留情况和建议下一步，不显示完成。环境初始化失败、登录或授权问题、进程启动失败等进入需要处理，不触发自动代码返修。超范围、删除用户数据、安装软件或改变系统设置，均不由自动修复隐含授权。

用户真正新提出的调整属于新一轮，不占上一轮修复次数；系统不得自动新建轮次绕过上限。恢复、重试或换卡片不得重置已使用次数。

| 设计状态 | 现有后端映射／边界 |
|---|---|
| 需求整理、待确认 | draft、awaiting_confirmation；对话卡片适配待实现 |
| 确认冻结、排队 | confirmed、queued；保留确认与启动门禁 |
| 工作中、验证中、自动修复 | running、verifying、safe_fixing；后端内部 round=1 为首次、round=2 为唯一修复，不等于用户新需求轮 |
| 等待查看、等待用户确认 | preview_ready、awaiting_user_acceptance；打开不等于验收 |
| 需要处理、未完成、取消、完成 | needs_user_action、failed、cancelled、completed；以真实后端结果呈现 |
| 状态核对中 | 展示层状态可信度，不能擅自改数据库或发起新执行 |

## 8. 预览、受阻与授权

打开预览只代表成功打开；用户必须实际查看并明确确认，Nova 验证门禁仍须满足。预览失败时说明“修改后的产品未能打开，本轮尚未完成”，列出已验证内容、无法检查的部分及停点；不得假装已经查看。

允许只读核对已有错误与证据。实际重试必须核对动作身份、支持能力与授权范围；不能把“打开页面”当“完成修复”。缺少运行条件时给手动指南和重新检查入口，不承诺自动安装、换端口代办或任意项目运行。用户点击“我已处理”后仍需真实复核。

三层错误文案：发生了什么→对已修改内容与记录的已知影响→下一步。保留情况不能确认时明确说尚在核对，不承诺数据一定安全或自动回退。

## 9. 执行中对话与控制

| 用户消息 | 处理 |
|---|---|
| 进度、原因 | 引用当前真实阶段、最近动作与更新时间；无可靠估算时不承诺剩余时间 |
| 新需求、参考附件 | 记录下一轮，不变更当前冻结范围；附件未解析须说明 |
| 暂停、停止、不要做了 | 先核对后端实际支持的控制能力和语义；无能力时如实说明，不能假装已暂停或停止 |
| 完工后调整 | 新轮确认卡，用户确认后才执行 |

只有后端确实支持并明确暂停点、恢复方式、停止影响及保留内容时，才展示暂停或停止按钮。请求已发送与实际已停止必须分开；关闭页面或应用窗口不代表执行停止。下一轮记录是草稿，不能自动执行。

## 10. 持续运行反馈（新版核心必需）

工作状态、时间线、验证结果自动更新，用户不必手动刷新；刷新按钮仅备用。订阅事件或轮询应读取真实后端记录，按任务隔离、去重并防旧响应覆盖当前选择；自动更新失败须主动可见，不能长期维持“开发中”。

| 字段 | 来源与显示规则 |
|---|---|
| 当前阶段 | 实际执行与验证事件；不能按计时器切换阶段 |
| 实际已用时间 | 以真实开始、结束与已知活动区间计算；重启后从持久记录恢复，未知区间标注；等待时长与执行时长分开 |
| 最近真实动作 | 可靠执行事件触发“正在读取项目”“正在修改文件”“正在运行检查”；保留动作发生时间 |
| 更新时间 | 区分最近动作时间、最近状态核对时间、最近成功数据更新时间；界面重绘不能冒充执行活动 |
| AI 输出摘要 | 标注来自执行 AI／自检，不能作为 Nova 独立验证结果 |
| Nova 事实验证 | 绑定文件、Git、命令、测试／构建等实际证据，显示通过、失败、未执行或无法确认 |

60 秒无新消息且已确认执行仍存活时显示：“任务仍在运行，暂时没有新的进度消息”。无法确认执行状态时显示：“暂时无法确认任务状态，Nova正在检查”；不能只凭计时器、旧 running 状态或成功刷新判定进程存活。检查未得结果时保留无法确认，明确下一步，不假装检查成功。

5 分钟无新消息时主动说明最后真实动作及状态核对结果，提供“继续等待”；暂停／停止仅按第 9 节能力门禁出现。继续等待只延续观察，不重启 AI，不重做动作。60 秒／5 分钟是初始默认阈值，后续按实测校准；新轮计时、重连或界面重绘不能掩盖原无消息时长。

进程退出、连接中断、执行受阻或刷新失败时主动显示错误和下一步。CLI 退出 0 但自查 blocked 仍属受阻。任务真实终态与展示状态核对失败须分开，不因暂时无法读取而伪造失败或完成。

计时器、活动动画只能表达等待／活动，不代表完成比例。无可靠工作量时不显示百分比；有依据的已检查项数也不能换算为整轮完成百分比。禁止定时轮播动作、固定剧本、模拟进度或静态统计充当真实工作反馈。不显示内部思维链；日志脱敏且默认折叠。

## 11. 网络恢复、重启与跨天

恢复后先读取任务、确认范围、动作身份与 attempt、进程可核实信息、已有文件和验证证据、已消耗修复机会、预览及用户确认记录，再决定续接。已成功动作不重做；started 但结果不明的动作先核对，无法确认时进入需要处理，不直接重复调用 AI。重连仅恢复观察不构成重试授权。

恢复消息说明最后已证实停点、已完成与未知部分。根据实际支持提供“核对上次工作”“查看已有结果”“补充下一轮要求”；不存在可续接执行会话时不得承诺从任意中断点继续。跨天插入日期分隔，保留原时间、确认记录及下一轮草稿。历史预览打开记录不能替代用户查看和验收确认。

## 12. 异常与边界

| 情况 | 行为 |
|---|---|
| 连续消息 | 按序记录，开始前合入确认卡；执行后按下一轮处理，不静默改变范围 |
| 没连接所选 AI | 保留输入，提示准备所选 AI；第二 AI 缺失不阻塞 |
| 网络断开、刷新失败 | 保留用户文本，展示错误与最近可信时间；重连先核对，不直接继续调用 |
| 历史按钮、快速连点、多窗口 | 前端锁定与后端幂等校验并用，失效请求返回当前状态 |
| 已验证项、无适用测试／构建 | 按现有后端证据与确认规则展示；不能用前端按钮跳过验证 |
| 修改保留情况不明 | 明确未知，先核对；不静默回滚用户改动 |

## 13. 动效与状态表达

保留 novaRise 240ms ease-out（上移 6px＋淡入）、三点 1.1s、旋转 0.9s、侧栏开合 200ms、贴底滚动约 300ms。活动动画旁必须有文字，无法确认状态时使用核对中提示，不持续暗示开发仍在进行。取消无依据的进度扫动和百分比。系统减少动态效果时取消位移与循环，滚动瞬间完成。

## 14. 无障碍与双语

Tab 顺序为左栏→对话流可用操作→输入框→发送→抽屉。焦点环 2px 主色、偏移 2px；最小点击高度 32px，主按钮 44px。状态必须图标加文字。新消息礼貌播报；不每秒播报计时，受阻、状态不明和结果变化须播报。英文按钮整块换行，1024×700 与 125%／150% 缩放下不裁切。语言切换不清空输入、不重启任务。关键文案见配套 UI/UX 文档。

> 生效版本：Nova v0.1.0，首个公开测试目标 v0.1.0-beta.1；2026-10-20 09:53 北京时间。
> 本轮已确认决策优先于旧版冲突内容。当前行为依据为 [交互设计说明](NOVA_V0.1.0_INTERACTION_DESIGN10200953.md)，与本文共同替代旧文件的冲突正文，旧文件原样归档。
> `Nova 原型.dc.html` 尚未同步；固定剧本与模拟数据只供设计评审。本版目标设计不代表已经实现；源码现状与待实现项见第 11 节。
> Nova 项目由 Codex 开发、Claude Code 独立审核。面向用户的 v0.1.0 使用单个执行 AI＋Nova 事实验证，不要求第二 AI，也不将本项目独立审核流程显示为产品运行门禁。

## 1. 设计定位与版本取舍

面向不懂代码、Git 或命令行的 Windows 用户，Nova 用普通语言协调一轮有范围、有证据、有用户确认的修改。用户应能快速看清：当前在做什么、状态是否可信、需要自己做什么。

保留最新版对话式主界面、固定输入区、轻量项目栏、折叠证据抽屉、双语与两套配色。不恢复旧版跨阶段页面向导，不让用户重新填写技术表单。初次引导和项目入口仍保留各自短向导。原型演示控制面板不属于正式产品导航。

本版将旧文档第 3／4 版叠加结构重整为一套有效规则，避免同一文件前后冲突。旧版文件与历史提示词仅供追溯；未来第二 AI 能力不作为当前连接、启动或完成条件，具体升级版本不由本轮确定。

## 2. 信息架构与页面骨架

首页保留新建产品（Beta）、打开电脑中的项目、从 GitHub 导入三个入口；首次引导保持语言选择、所选 AI 与必要工具检查和手动准备指引。新建产品使用一期唯一标准 Web 模板；GitHub 公开仓库导入遵循 Clone、读取 README／许可证、手动安装指南的边界，不自动安装依赖或运行陌生代码。这些按一期计划推进，不被核心界面首包范围默认删除或推到二期。

进入项目后：左栏为项目和历史轮次；中间是同一条对话流；右侧默认折叠，存放确认范围、下一轮草稿、变更和事实证据。首包不展示无真实来源的统计和任务完成进度环。

统一尺寸采用交互说明：左栏 230px／收起 48px，抽屉 286px／收起 48px，中间至少 480px；目标最小窗口 1024×700。空间不足时抽屉展开让左栏收起，关闭恢复。原 UI 文档中的 232／44／290px 是旧值，统一替换。正式配置与缩放兼容待验证。

## 3. 对话、确认与输入体验

输入区始终可用，提供“告诉 Nova 你想改什么”“现在做到哪一步了”等示例。Enter 发送，Shift+Enter 换行，输入法组字不发送；自动增高 1–6 行后内滚。回复、开发、验证期间均可提问，但继续输入不等于扩大当前执行范围。

Nova 将修改意见整理成同一对话流的需求确认卡，表达改哪里、改什么、哪些保持原样、怎样判断完成。主操作“开始修改”，辅助“我再补充一下”。信息明确即生成；影响实施的歧义只问必要问题，不设追问次数硬上限，不猜测关键范围。

示例（上下文已明确首页开始按钮）：

> 用户：按钮太小，改大一点，换成绿色。
>
> Nova：放大首页的开始按钮并改为绿色；按钮文字、点击功能及其他页面保持原样。完成后请查看是否清楚、方便点击。
>
> 开始修改／我再补充一下。

开始前补充要求合入本轮并更新确认卡；用户确认后冻结范围。执行中新增需求默认进入下一轮，明确提示，不静默扩大当前轮。验收时新调整也生成新轮确认卡，每轮都要确认，不提供小改动免确认路径。

历史卡片保留已确认版本与决定，按钮显示已处理／失效且不可重触发。后端须校验任务、轮次、确认版本及动作幂等；只禁用前端按钮不足以防重复。新版确认卡与现有启动门禁结合待实现。

附件选择、文件名展示和内容解析须区分。解析另包，未支持时明确提示未读取，不用“上传完成”暗示内容已理解。首包仅在清楚标明能力边界时保留入口；不依赖附件解析才能完成核心对话。

## 4. 真实工作状态与持续反馈

新版核心必需功能：工作状态、时间线、验证结果自动更新；手动刷新仅备用。工作卡固定显示真实阶段、实际已用时间、最近一次真实动作及动作时间、最近成功数据更新时间。必要时补充状态核对时间和可信度，避免“刚刷新”被理解为“刚有进展”。

可靠执行事件到达时，以普通语言更新“正在读取项目”“正在修改文件”“正在运行检查”。仅有 AI 输出摘要时标明来自执行 AI；Nova 的独立验证必须引用实际文件、Git、命令、测试／构建证据。两者采用不同标题与来源标签，不合并成笼统“已验证”。不得展示内部思维链，技术日志脱敏且默认折叠。

| 条件 | 主区域反馈 | 操作 |
|---|---|---|
| 60 秒无新消息，可靠核对确认执行仍存活 | 任务仍在运行，暂时没有新的进度消息 | 保留最后真实动作与核对时间 |
| 执行状态无法确认 | 暂时无法确认任务状态，Nova正在检查 | 继续只读核对；检查失败说明原因和下一步 |
| 5 分钟无新消息 | 主动说明等待时长、最后真实动作和状态核对结果 | 继续等待；仅当后端支持且语义明确时出现暂停或停止 |
| 退出、中断、受阻、刷新失败 | 发生了什么、修改与记录的已知影响、下一步 | 查看详情／重新核对／具体处理指引 |

60 秒／5 分钟为初始默认阈值，后续按实测校准。计时器、旧 running 状态、活动动画和成功获取旧记录都不能证明执行存活。继续等待只继续观察，不能调用 AI。关闭页面不代表停止执行；控制按钮须说明实际暂停点、恢复方式或停止影响，收到请求与实际停止分开展示。

实际已用时间以真实执行记录为依据；等待时长单独标注，重启从持久记录恢复，无法确定的执行时段注明未知。计时与活动动画只表示等待／活动，不能作为完成比例。无可靠工作量时不显示百分比；不按计时轮播动作，不用固定三项或 3/3、静态统计和进度环伪造工作反馈。自动刷新失败需主动提示，不能长期残留“开发中”。

## 5. 验证、一次修复与卡片状态

产品路径为单个执行 AI 开发及同次调用内自检→Nova 独立事实验证→必要时同一 AI 自动修复最多一轮→重新验证→结果查看→用户明确确认。首次开发和同次调用内自检不计自动返修次数。

只有 Nova 事实验证发现本轮范围内可安全修复的代码问题，才可自动交回同一个 AI 一轮。该轮可同时处理多个相关问题和文件，并非一行或一个文件。卡片显示“自动修复 1/1”、问题及影响，修复完成仍须重新验证。

修复后仍不通过即停止，显示未解决问题、修改保留情况与建议下一步；不显示完成、不继续返修、不自动新建需求轮绕过上限。环境初始化、登录／授权或进程启动失败进入“需要处理”，不走代码返修。超范围、删除用户数据、安装软件或修改系统设置不由自动修复隐含授权。

用户新提出的调整属于新轮，不占上一轮修复机会，但必须生成并确认新卡片。恢复、重试、界面切换不能重置已用修复次数。

卡片统一为标题＋文字状态、事实条目、动态信息、普通说明、折叠技术详情、一个主操作与必要辅助操作。主要状态为待确认、工作中、验证中、自动修复 1/1、需要处理、未完成、验证通过待查看、等待用户确认、本轮完成。成功色只表达具体已通过项；整轮完成强调仅用于后端门禁通过且用户已查看确认后。

## 6. 主流程与状态转换

```text
项目选择 → 需求对话 → 必要澄清 → 需求确认卡
补充要求 → 更新同轮确认卡 → 开始修改（冻结范围＋防重复启动）
工作中 → Nova事实验证
  ├─通过 → 等待查看 → 打开预览成功 → 等待用户明确确认
  │                                      ├─门禁满足且已查看确认 → 本轮完成
  │                                      └─提出新调整 → 新轮确认卡
  ├─本轮代码问题且可安全修复，未用机会 → 同一AI自动修复1/1 → 重新验证
  │                                                             ├─通过 → 等待查看
  │                                                             └─未过 → 停止，未完成
  └─环境／登录授权／启动等受阻 → 需要处理
任一阶段失联或重启 → 核对任务、动作和已有证据 → 确认真实停点后续接或需要处理
```

设计状态映射复用现有 draft、awaiting_confirmation、confirmed、queued、running、verifying、safe_fixing、preview_ready、awaiting_user_acceptance、needs_user_action、failed、cancelled、completed，详见交互说明第 7 节。展示层“正在核对状态”不新增执行副作用，不凭旧状态自动重试。

## 7. 结果查看、恢复与能力边界

“打开修改后的产品”仅证明成功打开，不证明功能验收。Nova 验证条件满足且用户查看并明确确认后，由后端验收门禁决定完成；前端不得另造完成判定。预览无法打开或用户无法查看时，说明已完成检查与无法确认部分，保留停点，不声称“这一轮完成了”。

应用重启或网络恢复后，先核对任务、确认范围、动作与 attempt、已有结果证据、执行存活信息、修复次数、用户确认和预览记录，再决定续接。已成功动作不重复；不确定动作先核对，不直接重调 AI。保留原错误与用户输入，不把重连当重试授权。

原型中的端口切换、安装软件、自动排障代办、任意项目启动均不因换界面自动进入本包。可展示既有证据、人工指南与真实复查入口；未支持的能力不放可执行按钮。需要登录、授权或环境处理时，只给具体下一步，不能承诺一键修好。用户称已处理后仍需真实检查。

## 10. 滚动、动效与无障碍

用户距底 ≤80px 时新消息贴底，上翻时出现“回到最新消息”，计时刷新不抢滚动。各区域独立滚动、输入区固定；长内容可展开，不撑破窗口。

新消息 240ms ease-out（上移 6px＋淡入）、侧栏 200ms、三点 1.1s、活动图标 0.9s；这些只表示等待／活动。减少动态效果时取消位移和循环。屏幕阅读器不每秒播报计时，但播报受阻、状态不明和验证结果变化。

Tab 覆盖全部可用操作，焦点环 2px 主色、偏移 2px。状态带图标与文字；正文对比度目标 ≥4.5:1。1024×700、小窗口、最大化、Windows 125%／150%、中英长文案均需迁移时验证。语言切换不得重启应用、清空输入或中断任务。以上为目标规范，本轮未运行视觉或原生 UI 验收。

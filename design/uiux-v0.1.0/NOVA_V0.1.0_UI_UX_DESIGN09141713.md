## 1. 现有原型问题分析（改版前的产品判断）

对上一版（18 视图、按钮跳转式）原型的逐条判断：

1. **是否仍以传统向导和页面跳转为主：** 是。18 个视图靠顶部导航与卡内按钮互相跳转，每个阶段是一个独立页面。
2. **是否必须不断选择和点击下一步：** 是。项目分析 → 三条路径 → 直接使用分步 → 任务确认 → 主界面 → 验证 → 预览 → 完工，用户平均要点 7–9 次才能走完一轮。
3. **能否随时补充需求：** 不能。输入框只存在于"项目主界面 · 需求对话"这一个阶段；进入开发、验证、预览后没有任何输入入口。
4. **能否随时询问进度和原因：** 不能。只有"Nova 为什么这样安排""查看技术详情"两个静态按钮，无法自由提问。
5. **新要求如何进入本轮或下一轮：** 未设计。上一版没有范围控制机制，用户中途提要求会与正在执行的任务冲突。
6. **用户是否被迫承担项目经理职责：** 部分是。用户要自己决定"现在该看哪个页面、该点哪个按钮"，等于在做流程编排。
7. **Nova 是否真正表现为项目经理：** 不充分。Nova 的"整理、判断、安排、核对"分散在多个页面的状态列表里，缺少一个说话的主体。
8. **是否适合 0 技术用户：** 文案层面适合（普通语言、技术详情折叠），但导航层面不适合——页面太多，用户需要建立心智地图。
9. **值得保留的界面元素：** 视觉 Token 全套；角色缩写标识（N / Cx / Cc）；三层错误结构（发生了什么 → 有没有影响 → 现在怎么做）；四态验证清单（已验证 / 需要修复 / 无法确认 / 等你查看）；心跳 + 真实用时；"只连接一个 AI"说明；v0.2.0 虚线卡；预览界面示意框；短向导（首启、首页、找项目、候选比较）。
10. **必须重新设计的工作流：** 项目分析→三条路径、直接使用分步、需求对话、任务确认、工作分配与 AI 状态、事实验证、修复、预览、排障、完工确认、跨天恢复——全部从"独立页面"改为"同一条项目对话流中的消息与嵌入卡片"。

**保留：** 全部视觉 Token 与组件语言；短向导三页（连接一个 AI、首页、找项目与候选比较）；v0.2.0 说明页；视觉规范页。

## 3. 新版主界面结构

进入项目后只有一个界面，三区：

- **左侧项目栏（232px，可收起为 44px）：** 当前项目、切换项目、＋新建任务、历史任务、项目概况与统计、即将推出、设置、回到首页。无文件树、无代码目录。
- **中间项目对话流（最大区域）：** 按时间顺序的用户消息、Nova 理解与追问、Nova 自动推进的状态行、嵌入式卡片（任务确认、AI 工作、事实验证、修复、预览、排障、完工结果、跨天恢复）。卡片选择后留在历史中，不跳页。
- **右侧详情抽屉（290px，默认收起）：** 项目概况、当前任务、已确认决定、暂不处理 / 下一轮、待解决问题、项目统计、本轮修改的功能、技术详情与原始日志。不打开抽屉也能完成全部主流程。

信息比例目标 60% 对话 / 25% 嵌入卡片 / 10% 关键选择 / 5% 技术详情，已按此控制卡片密度。

## 4. 固定输入框与文件拖拽

输入框固定在对话流底部，**在全部剧本中都存在**，AI 工作时也不禁用。占位文案：
中文「继续告诉 Nova 你的想法，或询问当前进度……」／英文「Tell Nova what you'd like to add, change, or understand…」。

上方一行示例胶囊降低空框压力：现在做到哪一步了？／为什么这样处理？／先让我看看效果／先暂停一下。
下方一行说明支持拖入截图、图片、PDF、Word、项目说明、报错截图，并提供「模拟拖入一个文件」按钮演示。

拖拽体验：拖入时整个对话区出现虚线覆盖层「把文件放在这里」；放下后文件以附件气泡进入对话，Nova 立即追问「你希望我把这个文件作为设计参考，还是希望修改它对应的功能？」，给出`作为参考（推荐）`／`修改相关功能`，并保留「或者直接告诉我你希望怎样使用它……」。不提供节点拖动排序——流程编排由 Nova 承担。

## 5. 点击次数减少说明

自动推进（无需点击）：读取 README、分析项目、整理需求、生成任务摘要、交给 AI、收集结果、事实验证、一次自动修复、重新验证、安全的排障处理（如换端口）、整理报告、记录新要求到下一轮。

仍然要求点击的只有五处：① 开始前的任务确认卡；② 会产生明显不同结果的选择（如没有记录的月份显示什么）；③ 需要安装系统软件 / 权限 / 账号 / 付费（如安装 Node.js）；④ 打开并查看实际效果；⑤ 完工确认。

一轮二次开发的必要点击从上一版的 7–9 次降到 **3 次**（确认任务 → 打开产品 → 我已经看过，符合需要）。

## 7. v0.1.0 与 v0.2.0 边界

v0.1.0 只需一个 AI（Codex 或 Claude Code），流程为：导入或恢复 → 判断能否直接使用 → 安装启动指导 → 持续对话 → Nova 整理本轮任务 → 一个 AI 开发 → Nova 事实验证 → 必要时修复一次 → 重新验证 → 打开产品 → 用户验收 → 保存项目记忆。完成绿色只在三项齐备后出现。

v0.2.0（仅"即将推出"页 + 左栏入口，虚线卡片 + `v0.2.0` 标签）：第二 AI 独立审核、首次/二次审核、用量提醒与 20% 接力、AI 安全切换、用户级 Git 回滚、GitHub 授权与 Push、Actions 构建。对话流中没有任何审核节点。

各自分工：
- **B（主方案）**：对中国普通用户熟悉度最高，上手成本接近零；绿色即"可用/通过"的直觉一致。代价是绿色同时承担主色与通过色，验证结果的语义区分要靠图标与文字承担。
- **A（品牌化备选）**：解决 B 的三个长期问题——① 视觉差异化（B 让 Nova 看起来像微信插件）；② 预期错位（微信绿暗示"聊天等回复"，A 的纸质感更贴合"工作台"的真实行为）；③ 品牌资产与合规（`#07C160`/`#95EC69` 是腾讯标志性组合，A 是可注册、可延展到官网/文档/安装包的自有色板）。作为后续品牌升级的目标形态保留。

## 17. 主流程（可连续操作）

开场（Nova 自我介绍 + 3 个建议）→ ① 粘贴 GitHub 地址 / 帮我找 / 打开本地 → 分析状态两步 → 普通语言产品介绍 + 「我看到的情况」卡（能否直接用 / 是否适合改 / 界面语言）→ ② 先打开看看（准备环境 → 可使用卡 → 打开产品）或 ③ 提出修改要求（最多追问 1 个问题 → 需求总结卡 3 项）→ ④ 「就这样开始」→ 工作卡（交给 Codex、进度条、任务 3 项状态、已用时长秒级跳动、最新动作、技术细节折叠）→ 工作中用户追加要求 → 「已记录，排在下一步」并在工作卡追加「下一轮已记录 N 项」→ ⑤ 事实验证：1 项未通过 → 影响说明 → 安全修复 → 复检 → 3/3 通过 → ⑥ 打开修改后的产品 → 启动失败 → Nova 自查 → 「还差一步」一次只给一个操作（开始安装 / 我没看到这个页面 / 还是无法打开 → 由 Nova 代办）→ 复检通过 → 打开产品 → ⑦ 完工验收卡（已完成 / 我检查过什么 / 需要留意）→ 还需要调整（回到正常对话，小改动直接做完再给看）或 我满意，完成项目 → 项目记录卡。

跨天恢复：演示面板「跨天恢复」进入——历史两条消息 + 恢复消息 +「继续上次工作 / 先打开当前结果 / 我想补充一个要求」。

## 21. 自检报告（逐项）

1. **用户可否真正自由输入？** 可以。真实 `textarea`，Enter 发送、Shift+Enter 换行、自动增高、粘贴可用。
2. **点击按钮是否形成用户消息？** 是。全部建议按钮与卡片操作按钮都先生成一条自然语言用户消息。
3. **Nova 是否在同一对话流中回复？** 是。没有任何页面跳转，只有消息追加。
4. **用户可否随时追问？** 可以。输入框在所有阶段可用，未做禁用。
5. **AI 工作时可否追加要求？** 可以。追加后 Nova 回复"排在下一步"，工作卡出现「下一轮已记录 N 项」。
6. **长时间工作是否持续反馈？** 是。动态状态点、进度条扫动、秒级计时、最新动作每 3 秒更新。
7. **是否避免展示内部思维链？** 是。只显示可观察动作（读取说明、确认启动方式、整理要求、正在修改首页文字、正在检查、正在安全修复）；无推理过程、无终端输出、无代码。
8. **中英文是否完成？** 完成。含演示面板在内全部界面字符串双语，切换即时全量生效。
9. **正式界面是否移除剧本切换器？** 已移除。剧本仅存在于界面外的深色演示面板，面板可隐藏，并明确标注"不属于正式产品界面"。
10. **能否看到修改后的真实效果入口？** 能。验证通过卡、可打开卡、完工验收卡均提供「打开修改后的产品」主按钮。
11. **预览失败是否一次只要求一个操作？** 是。每张排障卡只有一个主操作，另一个按钮仅用于"我做不到"，最终由 Nova 代办。
12. **重新打开是否有恢复体验？** 有（跨天恢复场景）：历史对话 + 简短恢复消息 + 三个续接选项。**真实持久化未实现。**
13. **v0.1.0 是否没有双 AI 审核？** 没有。主流程只有一个执行 AI（Codex）+ Nova 自己核对；v0.2.0 内容已从产品中完全移除。
14. **哪些是真实、哪些是模拟？** 见第 20 节。

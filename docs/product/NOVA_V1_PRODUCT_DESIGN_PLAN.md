**版本：** V1.1  
**产品代号：** Nova Code  
**目标平台：** Windows x64  
**技术基础：** Tauri 2 + Vue + Rust

## 一、产品结论

Nova V1 是一个运行在用户本机的 AI 编程协作客户端。它不重新开发 Codex 或 Claude Code，而是在两者之上提供统一的项目上下文和任务交接能力。

第一版只解决两个紧密关联的核心问题：

> 1. 默认由 Codex 开发、Claude Code 审核；用户也可以反向选择 Claude Code 开发、Codex 审核。
> 2. Codex 用量耗尽、上下文不足或执行中断后，用户确认一次即可由 Claude Code 携带完整项目上下文继续工作。

产品口号：

> **换 AI，不换项目，不重新解释。**

核心原则：

> **记忆属于项目，不属于某一个 AI。**

## 二、V1目标

### 2.1 必须实现

1. 用户选择一个本地代码目录作为当前工作项目。
2. Nova在本地建立该项目的上下文档案。
3. Nova检测本机是否已经安装并可调用Codex CLI和Claude Code CLI。
4. 用户在Nova中填写开发任务。默认使用“Codex开发、Claude Code审核”，也可以切换为“Claude Code开发、Codex审核”。
5. Nova记录原始需求、执行工具、任务状态和时间信息。
6. 开发AI完成后，Nova收集 `Git Diff`、`git status`、任务总结和测试结果。
7. Nova根据真实数据生成结构化交接包。
8. 默认模式下，用户点击“让Claude审核”，Nova启动Claude Code执行只读审核；反向模式下，用户点击“让Codex审核”。
9. 审核AI收到完整任务背景、变更、测试证据和审核规则。
10. 审核AI输出结构化审核结论：`APPROVE`、`CONDITIONAL PASS`或`BLOCK`。
11. 如果需要修复，用户可以把问题交回原开发AI处理。
12. 开发AI获得原始任务、自己的修改和审核问题，继续处理。
13. Codex用量耗尽、上下文不足、失败或不可用时，Nova必须保存当前状态，并让用户确认后由Claude Code无缝继续当前任务。
14. 关闭Nova后重新打开，任务、上下文、交接历史仍然存在。
15. 所有用户界面、按钮、状态、提示和错误信息必须同时提供简体中文与英文版本，并支持随时切换。

### 2.2 成功标准

V1成功不以“支持多少模型”衡量，而以以下体验衡量：

- 用户不复制提示词，也能把开发AI的结果交给另一个AI审核。
- 默认模式下Claude Code能够准确审核Codex；反向模式下Codex能够准确审核Claude Code。
- 审核AI提出问题后，原开发AI能够接着修复，而不是从头理解项目。
- Codex明确返回用量限制后，用户最多确认一次，Claude Code即可在同一项目、同一任务和同一上下文中继续。
- 应用重启后，当前任务和交接状态不丢失。
- AI输出不得冒充Git、测试或文件系统的真实状态。
- 中英文切换后，当前任务、输入内容、运行状态和页面位置不丢失。

## 三、明确不做的内容

Nova V1不包含：

- 用户注册、登录、会员或付费。
- SDKMAX账号同步、余额、API Key自动创建。
- 400模型列表、场景模型组或SDKMAX AI入口。
- 多项目管理、项目看板、任务看板、任务依赖。
- GitHub Actions、代码构建、上线部署、线上运营。
- 本地测试工作流、回滚流程、生产审批流程的自动编排。
- Jira、Trello、Asana式项目管理。
- 完整IDE、代码编辑器或Cursor替代品。
- 重新实现Codex或Claude Code的Agent能力。
- 自动读取Codex、Claude Code的云端内部记忆。
- 未经用户确认就在后台擅自切换AI。V1允许检测明确的Codex限额错误并主动弹出接力确认。
- 多人协作、云端同步、移动端和网页端。
- MCP市场、插件市场和复杂Agent路由。

说明：Nova可以收集Codex实际执行过的测试结果，但V1不负责设计和控制完整的测试、构建、上线工作流。

## 四、目标用户与核心场景

### 4.1 目标用户

第一版只服务以下用户：

- 同时使用Codex和Claude Code的个人开发者。
- 使用“一个AI开发、另一个AI审核”方式完成代码任务的用户。
- 不愿意反复复制项目背景、开发结果和审核报告的用户。
- 需要在一个AI不可用时，把当前工作交给另一个AI继续的用户。

### 4.2 核心场景

#### 场景A：Codex开发，Claude Code审核（默认模式）

用户提出任务 → Codex开发 → Nova收集变更 → Claude Code只读审核 → 输出结论。

#### 场景B：Claude Code开发，Codex审核（可选模式）

用户提出任务 → Claude Code开发 → Nova收集变更 → Codex只读审核 → 输出结论。

#### 场景C：审核发现问题，交回开发AI修复

审核AI输出问题清单 → 用户确认 → Nova生成修复交接包 → 原开发AI修复 → 审核AI复审。

#### 场景D：Codex用量耗尽，Claude Code继续

Codex明确返回用量限制、上下文不足或意外中断 → Nova冻结并保存当前任务与Git状态 → 弹出接力确认 → 用户确认 → Claude Code基于交接包在同一项目中继续。

#### 场景E：应用关闭后恢复

用户关闭Nova → 重新打开 → Nova恢复当前项目、任务、执行记录和最近一次交接状态。

## 五、产品使用流程

## 5.1 首次启动

### 页面一：欢迎页

显示内容：

- Nova Code名称与一句话说明。
- “Codex与Claude Code在同一个项目中连续工作”。
- 主按钮：“开始使用”。
- 右上角语言入口：“中文 / EN”。

不出现注册和登录。

### 页面二：环境检测

Nova自动检测：

- Codex CLI是否安装。
- Claude Code CLI是否安装。
- Git是否安装。
- 对应命令是否可执行。

状态分为：

- 已安装，可使用。
- 已安装，但需要登录或授权。
- 未安装。
- 检测失败。

Nova不得读取或展示用户密码、Token或第三方账号凭据。需要登录时，打开对应工具的官方登录流程或终端，由用户完成。

### 页面三：选择项目目录

用户点击“选择代码项目”，通过系统目录选择器选择一个本地目录，例如：

`D:\sdkmax`

Nova检查：

- 目录是否存在。
- 是否可读。
- 是否为Git仓库。
- 当前分支。
- 是否存在未提交修改。

V1一次只打开一个项目，不提供项目列表、收藏、分类或项目管理。

选择完成后进入工作台。

## 5.2 创建并执行任务

1. 用户在任务输入框填写任务要求。
2. 用户选择协作模式。默认是“Codex开发 → Claude Code审核”；可切换为“Claude Code开发 → Codex审核”。
3. 默认主操作为“交给Codex”；反向模式下为“交给Claude Code”。
4. Nova在执行前展示本次交给AI的信息摘要和允许访问的项目目录。
5. 用户确认后，Nova启动对应CLI子进程。
6. 界面显示实时输出、运行状态、中止按钮和已运行时间。
7. 用户可以展开原始终端输出，但默认看到简化进度。
8. 执行结束后，Nova收集真实Git状态、Git Diff、进程退出状态和AI总结。

## 5.3 交给另一个AI审核

1. 默认模式下Codex执行完成后，主按钮变为“让Claude审核”；反向模式下显示“让Codex审核”。
2. 用户点击后先看到“审核交接预览”。
3. 预览内容包括：原始需求、项目规则、Codex总结、修改文件、Git Diff、测试证据和审核指令。
4. 用户确认后，Nova启动审核AI。
5. 审核AI默认只读，不允许修改文件。
6. 审核AI输出结构化审核报告。
7. Nova显示审核结论、阻断问题、一般问题和建议。

## 5.4 交回开发AI修复

1. 当结论为`CONDITIONAL PASS`或`BLOCK`时，显示“交回Codex修复”或“交回Claude Code修复”。
2. Nova生成修复交接包，包含原始需求、已有修改、审核问题清单和当前Git状态。
3. 用户预览并确认后启动原开发AI。
4. 修复完成后，可以再次交给审核AI复审。

## 5.5 中断与切换

当Codex进程明确返回用量限额、上下文限制、异常退出或用户手动中止时：

1. Nova立即保存任务事件和当前Git状态。
2. 任务状态显示为“已中断”，不能显示“已完成”。
3. 对明确的用量限制，优先展示：“Claude Code继续工作”；同时提供“重试Codex”和“暂时保存”。
4. 用户确认后，Nova生成中断交接包并启动Claude Code。
5. Claude Code收到原始任务、已完成内容、当前Diff、必要终端证据、未完成步骤和中断原因。
6. Claude Code接手成功后，界面显示“Claude Code已接手”，继续沿用同一个任务窗口和任务时间线，不新建孤立会话。

V1不自动切换。所有跨AI接力都必须由用户确认。

## 5.6 中英文切换

1. 首次启动默认跟随Windows系统语言；简体中文环境显示中文，其他环境默认显示英文。
2. 用户可以在欢迎页和设置菜单中随时切换“简体中文 / English”。
3. 切换语言即时生效，不重启应用、不清空输入、不打断正在执行的CLI任务。
4. 项目路径、代码、Git Diff、终端原始输出和AI原始回复保持原文，不做机器翻译。
5. Nova自身的按钮、菜单、状态、引导、错误提示、权限说明和空状态必须完整双语。
6. 审核模板和交接模板根据界面语言生成，但技术标识如`APPROVE`、`CONDITIONAL PASS`、`BLOCK`保持英文不变。

## 六、界面信息架构

V1只设计五个界面状态，不设置复杂导航。

### 6.1 欢迎/环境检测页

组成：

- 产品名称和价值说明。
- Codex、Claude Code、Git三个检测项。
- 修复或重新检测按钮。
- 选择项目按钮。

### 6.2 主工作台

布局建议：

#### 顶部栏

- Nova Code。
- 当前项目名称和目录。
- Codex、Claude Code可用状态。
- 当前协作模式：“Codex开发 → Claude审核”或“Claude开发 → Codex审核”。
- 中英文切换入口。
- 设置入口。

#### 左侧窄栏

- 当前任务。
- 上一次执行。
- 当前Git状态。

V1不展示多个项目，不做项目管理导航。

#### 中央主区域

- 当前任务标题。
- 当前执行者。
- 任务状态。
- AI交互和终端输出。
- 任务摘要。
- 主要操作按钮。

#### 右侧上下文抽屉

默认收起，用户需要时打开：

- 原始需求。
- 项目规则。
- 修改文件。
- Git Diff。
- 测试证据。
- 交接包预览。

### 6.3 执行中状态

显示：

- 当前AI：Codex或Claude Code。
- 已运行时间。
- 实时简化状态。
- 可展开终端原始输出。
- “中止任务”按钮。

必须清晰区分：运行中、用户取消、执行失败、输出中断、执行成功。

### 6.4 审核结果页

显示：

- 审核结论。
- 阻断问题。
- 一般问题。
- 建议。
- 被审核的Commit或工作区快照标识。
- “交回开发AI修复”“重新审核”“查看完整报告”。具体按钮根据当前开发AI显示为Codex或Claude Code。

### 6.5 接力确认弹窗

每次切换AI前出现，显示：

- 从哪个AI切换到哪个AI。
- 新AI的任务角色：继续开发或只读审核。
- 即将传递的信息。
- 文件权限。
- 当前Git状态。
- “取消”和“确认接力”。

### 6.6 视觉风格与布局规范

#### 风格方向

Nova应借鉴Codex桌面应用和Claude Code的共同体验特征：专业、安静、以内容和任务为中心、弱装饰、强可读性。可以借鉴其信息密度、交互节奏、终端感和对话结构，但不得复制对方商标、Logo、专有插图、品牌色组合或像素级界面。

建议采用两种可由Claude提供比较稿的方向，最终只选择一种实施：

- **Codex倾向方案：** 中性灰白/深灰背景，简洁侧栏，清晰任务标题，大面积内容区，少量高对比主按钮。
- **Claude Code倾向方案：** 温暖中性色，柔和分隔，终端与文本协作感更强，强调思考过程与审核结果的层级。

无论采用哪种方向，都必须保持Nova自己的品牌识别：使用Nova名称、自有图标和统一组件，不伪装成OpenAI或Anthropic官方产品。

#### 布局原则

1. 符合Windows桌面软件常见使用习惯：顶部显示当前上下文，左侧放稳定导航或任务摘要，中间为主工作区，右侧为可收起详情。
2. 用户视线顺序应为：项目 → 当前任务 → 当前AI角色 → 执行内容 → 下一步主操作。
3. 输入框固定在主内容区底部附近，但不能遮挡输出和审核结果。
4. 原始终端输出、Git Diff和交接详情按需展开，不与主任务信息争夺注意力。
5. 主操作按钮靠近当前结果，禁止把“审核”“继续”“中止”等关键按钮分散到多个区域。
6. 适配1366×768、1440×900和1920×1080；较小窗口下优先收起右侧抽屉，不压缩正文到不可读。
7. 默认支持浅色、深色和跟随系统三种主题。

#### 用户体验要求

1. 首次使用从启动到创建第一个任务不超过三个主要步骤：环境检测 → 选择目录 → 输入任务。
2. 默认协作模式预先选中，不要求用户理解复杂配置。
3. 任何一次AI切换前只做一次清晰确认，避免连续弹窗。
4. 正常操作完成后，界面自动把用户带到唯一合理的下一步。
5. 失败提示必须同时说明“发生了什么、工作是否已保存、用户现在可以做什么”。
6. 中英文文案保持语义一致，英文不是中文的机械直译，应符合开发工具用语习惯。

## 七、关键界面规则

1. 主界面只能有一个高优先级主按钮。
2. 主按钮随任务状态变化：
   - 默认模式尚未开始：`交给Codex`
   - 反向模式尚未开始：`交给Claude Code`
   - 开发AI运行中：`中止任务`
   - 默认模式开发完成：`让Claude审核`
   - 反向模式开发完成：`让Codex审核`
   - 审核发现问题：`交回开发AI修复`
   - 审核通过：`完成本次任务`
   - Codex用量耗尽或中断：`交给Claude Code继续`
3. 不把400个模型显示在主界面。
4. 不使用“内部记忆迁移”等难以理解的术语，统一使用“项目上下文”“工作接力”。
5. AI生成的总结与系统采集的Git、文件和进程事实必须在视觉上区分。
6. 默认显示简洁结果，提供“查看详情”展开原始证据。
7. 任何审核AI都必须明显显示“只读审核”。
8. 发生中断时必须显示未完成状态，禁止静默重试后伪装成完整结果。
9. 协作模式必须在任务开始前可见；任务执行后如需交换开发/审核角色，必须通过明确的新一轮接力完成。
10. 中英文切换入口固定、易发现，但不得抢占主操作视觉层级。

## 八、项目上下文与“记忆互通”设计

### 8.1 上下文构成

Nova保存的上下文分为四类：

#### 用户事实

- 原始任务。
- 用户补充要求。
- 用户确认的验收标准。

#### 项目事实

- 项目路径。
- Git分支。
- 基线Commit。
- 当前Git状态。
- 修改文件和Diff。

#### AI执行记录

- 执行工具。
- 开始、结束和退出状态。
- AI输出摘要。
- AI声称执行的测试。

#### 系统验证证据

- Nova实际执行或读取到的Git命令结果。
- 子进程退出码。
- 实际捕获的测试输出。
- 中断、取消和错误原因。

### 8.2 本地存储

建议默认将Nova自身数据保存在Windows用户应用数据目录，不直接污染代码仓库。

推荐逻辑结构：

```text
NovaData/
└── workspace-{hash}/
    ├── workspace.json
    ├── context.json
    ├── current-task.json
    ├── events.jsonl
    ├── handoffs/
    └── reviews/
```

V1不默认在项目中创建`.sdkmax/`或`.nova/`目录。后续如需团队共享，再单独设计可提交版本的`NOVA.md`。

### 8.3 上下文压缩

交接时不应把全部终端日志无脑发送给下一个AI。交接包按以下顺序组织：

1. 原始任务与用户约束。
2. 当前角色和具体目标。
3. 项目规则。
4. 已完成工作摘要。
5. 当前Git状态与修改文件。
6. 与任务相关的Diff。
7. 测试证据。
8. 未完成事项和风险。
9. 必要的原始输出片段。

如果内容超过CLI可接受范围，应先压缩历史摘要，但原始数据继续保存在本地，不能删除。

## 十、技术架构建议

### 10.1 模块划分

#### Vue前端

- 欢迎与环境检测。
- 项目目录选择。
- 工作台状态展示。
- 实时输出展示。
- 上下文抽屉。
- 接力预览与确认。
- 审核结果解析和展示。
- 开发/审核角色切换。
- 中文/英文即时切换。

#### Tauri/Rust核心

- 安全调用系统目录选择器。
- 检测Codex、Claude Code和Git命令。
- 管理CLI子进程生命周期。
- 流式读取stdout/stderr。
- 支持用户取消和进程终止。
- 读取Git状态和Diff。
- 生成交接包。
- 本地数据原子写入。
- 敏感信息脱敏。

#### CLI适配器

每个AI工具建立独立适配器，不把输出解析逻辑散落在UI中：

```text
AgentAdapter
├── detect()
├── validateAuthState()
├── startTask()
├── streamEvents()
├── cancel()
├── normalizeExit()
└── collectSummary()
```

实现：

- `CodexAdapter`
- `ClaudeCodeAdapter`

第三方CLI参数、输出格式或登录机制变化时，只修改相应适配器。

同一个适配器必须支持两种运行角色：

- `developer`：允许在用户授权范围内修改项目。
- `reviewer`：只读审核，禁止修改项目。

### 10.2 国际化架构

- 前端使用统一i18n资源，不允许在组件中散落硬编码的中英文按钮。
- 至少包含`zh-CN`和`en`两个语言包。
- 所有新增界面必须同时提交两种语言键值。
- 日期、时间和数字按当前语言区域格式化。
- 用户选择保存在本地；未选择时跟随Windows系统语言。
- 技术内容、代码、路径、Git Diff和CLI原始输出保持原文。
- i18n缺失键在开发环境中应明显报警，生产环境回退到英文。

### 10.3 任务状态机

```text
IDLE
  → READY
  → DEVELOPER_RUNNING
  → DEVELOPER_COMPLETED
  → REVIEW_READY
  → REVIEWER_RUNNING
  → APPROVED
  → CHANGES_REQUESTED
  → DEVELOPER_FIXING
  → REVIEW_READY

接力状态：
DEVELOPER_RUNNING → HANDOFF_REQUIRED
HANDOFF_REQUIRED → HANDOFF_CONFIRMED
HANDOFF_CONFIRMED → CONTINUATION_RUNNING

异常状态：
RUNNING → CANCELLED
RUNNING → INTERRUPTED
RUNNING → FAILED
```

所有状态变更必须写入事件记录。应用重启后根据事件和当前任务文件恢复，不能仅依赖前端内存。

任务数据必须保存以下角色字段，避免流程与某个AI硬编码绑定：

```text
developer_agent: codex | claude_code
reviewer_agent: claude_code | codex
current_agent: codex | claude_code
current_role: developer | reviewer | continuation
```

### 10.4 用量限制识别与无缝衔接

1. CodexAdapter应优先使用CLI提供的结构化错误类型或退出信息识别限额。
2. 如果只能依赖文本匹配，匹配规则必须版本化、可测试，并区分“明确限额”和“疑似限额”。
3. 明确限额：自动保存现场并弹出“Claude Code继续工作”。
4. 疑似限额：显示原始错误，允许用户选择，不得自动宣称额度耗尽。
5. 接力前重新读取当前Git和文件状态，确保交接包反映磁盘真实情况。
6. “无缝”标准是用户无需复制背景、无需重新选择项目、最多确认一次；不是迁移第三方AI不可见的内部推理状态。
7. 如果Claude Code未安装、未登录或不可用，必须保存任务并给出修复入口，不能丢弃当前现场。

### 10.5 数据真实性

- Git状态由Nova调用Git读取，不采信AI口述。
- 修改文件由Git和文件系统确认。
- 测试只有捕获到命令和输出时才标记“有证据”。
- AI仅在文本中声称测试通过时，显示“AI报告通过，未由Nova验证”。
- 子进程输出不完整时标记`INTERRUPTED`。
- 禁止在SSE、stdout或stderr中断后静默生成“已完成”。

### 10.6 安全边界

- 只允许AI访问用户明确选择的项目目录。
- 所有审核角色默认只读，无论审核者是Claude Code还是Codex。
- 用户确认前不得切换执行工具。
- 不读取或上传第三方凭据。
- 不把完整项目内容上传到Nova自建服务器；V1全部本地运行。
- 记录命令时对Token、Key和密码模式进行脱敏。
- 中止任务必须终止对应子进程及其必要的子进程树。

## 十二、验收测试

### 12.1 正常闭环

1. 选择测试仓库。
2. 创建一个小型代码修改任务。
3. Codex完成修改。
4. Nova正确显示修改文件和Diff。
5. 点击“让Claude审核”。
6. Claude获得完整交接包并保持只读。
7. Claude输出三个标准结论之一。
8. 发现问题时交回Codex修复。
9. 再次审核并最终通过。

再完整执行一次反向闭环：

1. 选择“Claude Code开发 → Codex审核”。
2. Claude Code完成修改。
3. Nova采集真实Diff和执行证据。
4. Codex保持只读并输出标准审核结论。
5. 发现问题时交回Claude Code修复。

### 12.2 中断恢复

- Codex运行时手工中止。
- 强制关闭Nova后重新打开。
- CLI异常退出。
- 终端输出不完整。
- Git仓库在任务中被外部修改。
- 模拟Codex返回明确用量限制，确认Nova保存现场并成功交给Claude Code继续。
- 模拟疑似限额错误，确认Nova不会误判为确定的额度耗尽。

每种情况下均不得丢失原始任务，也不得错误显示为“任务完成”。

### 12.3 安全测试

- Claude Code作为审核者时不能修改项目文件。
- Codex作为审核者时不能修改项目文件。
- 未选择的目录不能被访问。
- 日志中的API Key和Token被脱敏。
- 有未提交修改时明确提示基线状态。
- 两个AI不能同时修改同一工作区。

### 12.4 V1通过标准

- 正常闭环连续执行3次成功。
- 应用重启恢复测试通过。
- 取消和中断状态准确。
- Git证据与实际仓库一致。
- Claude Code审核没有修改文件。
- Codex审核没有修改文件。
- Codex用量耗尽到Claude Code继续的完整接力连续执行3次成功。
- 默认模式和反向模式各完成至少3次端到端闭环。
- 中文、英文下所有P0页面无缺失文案、截断或布局溢出。
- 运行中切换界面语言不会中断任务或丢失输入。
- 用户全程无需手工复制交接提示词。

## 必须区分的两个不同概念

**A. Nova 项目自身的研发协作方式**：本仓库的开发流程使用 Claude Code 完成代码修改，Codex 进行独立只读复审。这是本项目的工程实践，与 Nova 产品本身提供给最终用户的功能无关，不得写成 Nova v0.1.0 的产品需求。

**B. Nova v0.1.0 产品提供给用户的运行流程**：用户只需选择并连接**一个**开发 AI（Codex 或 Claude Code 二选一）；Nova 自己独立验证真实文件、Git 状态、测试、构建，并支持真实效果预览和用户验收；第二个 AI 的独立审核能力是 v0.2.0 的功能，不是 v0.1.0 的启动或完成门禁。

## v0.1.0 P0（必须完成）

1. 打开/注册本地项目；
2. 确认任务需求；
3. 选择一个开发 AI（Codex 或 Claude Code）；
4. 该开发 AI 修改真实项目文件；
5. Nova 独立验证 Git/文件/测试/构建证据；
6. 验证失败时，允许同一开发 AI 进行一次安全修复并重新验证；
7. 打开真实效果预览；
8. 用户验收或拒绝结果；
9. 保存结果证据、项目记忆和可恢复的任务状态。

只连接 Codex（或只连接 Claude Code）时，以上主路径必须完整可运行；未选择/未连接/未登录/不受信任的另一个 AI，绝不能阻塞已选开发 AI 的主路径。

## 明确推迟到 v0.2.0 的功能

1. 强制第二 AI 独立审核；
2. 要求开发者和审核者必须是不同的 AI；
3. Codex/Claude Code 角色互换作为产品主路径能力；
4. 开发、首审、修复、复审四段强制闭环流程；
5. `FIRST_REVIEW.md`/`SECOND_REVIEW.md` 作为 v0.1.0 必需产物；
6. 第二 AI 不可用时阻止任务启动或完成；
7. 用户级 Git 回滚；
8. GitHub 构建和远端发布相关门禁。

## 与代码实现的对应关系

本文件描述的范围已经在以下代码中落实并通过 Codex 复审（工作包 1，`CODEX_PHASE3_SINGLE_AI_RUNTIME_FINAL_REREVIEW09232135.md` 及后续复审均确认）：

- `apps/desktop/src-tauri/src/core_loop.rs` 的 `run_core_loop`：v0.1.0 唯一的生产入口，只有一个开发 AI，从不探测或要求第二个 AI；双 AI 编排逻辑被隔离在未被任何 command 调用的 `run_core_loop_dual_ai_v0_2` 中。

## 4. 为什么这样分包：首包范围与交付切片

旧表单技术负担与执行事实可信度是同一条用户路径的问题。只做外壳会把“无法理解需求、无法确认存活、无法打开结果”的缺口藏进更漂亮的界面；一次包揽导入/模板/智能排障又会失去最小可审查范围。因此首包只以**已有本地项目**完成一条真实路径，按下列顺序分可审查切片交付，前置契约未确认则暂停对应开发，不并行启动其他阶段：

1. **契约切片**：项目/任务归属、需求草稿及版本确认、下一轮草稿、只读运行状态/存活投影、受控结果打开的API设计与隔离测试先行。对schema、额外CLI调用及预览边界取得PM具体选择后才能实施；绝不改写现有已确认四字段来偷省草稿层。
2. **工作台切片**：Vue项目栏/对话流/固定输入/确认卡/工作卡/受阻卡/结果卡/技术抽屉绑定真实接口，同一会话不跨页面管理阶段。B绿主方案、A暖纸用token支持，中英同时交付，不以后补文案为借口留中文写死的新卡。
3. **集成切片**：完整权限/并发/恢复/双语/可访问性回归，Claude独立审核，候选CI，按备份方案安装，限定夹具真实流程和用户实际效果验收。任一切片不通过不把UIUX-01写成完成。

**包含**：已注册/本地选择入口、历史任务选择、普通语言需求和四项确认、开始前补充/执行后下一轮、安全输入保护、事实状态与耗时、真正受阻原因及支持的下一步、限定预览/人工查看、用户接受、七报告/证据/命令查看与正常同步、基础所选AI准备说明、双语与键盘/缩放。

**不包含**：附件内容解析/上传、自动安装或登录、全能排障/换端口、任意程序启动、生产部署、第二AI审核、SDKMAX充值/模型商城、自然语言GitHub搜索、统计看板、额度接力、产品内Git回滚。GitHub公开URL导入、新建唯一标准模板Beta、完整首次引导属于后续**一期包**，不是删除或偷挪二期；自然语言搜索推荐才二期。本轮不启动这些包。

## 5. 用户的实际操作路径（目标，不是当前已实现）

1. 打开后选已有项目或“打开电脑中的项目”。路径规范化匹配已有项目；选中历史任务只读取，不创建项目/任务。所选AI尚未准备好时显示一个具体手动准备入口，用户文本保留。
2. 在常驻输入区描述想改什么。Nova给普通语言复述；缺关键信息才追问，四项“改哪里/改什么/保持原样/怎样判断完成”在同一流确认卡中展开。执行AI选择为次级信息，另一AI不用连接。
3. “我再补充一下”修改**未确认草稿**，保留历史版本；用户“开始修改”绑定精确草稿revision，服务端确认冻结后才能启动。自动发现测试命令仍按现有确认/不适用门禁，若需要用户确认用普通语言卡解释，不静默忽略。
4. 执行中卡显示实际状态、活动/未知时间段、最后真实事件及时间、最近成功刷新时间。用户问进度只读取事实；新要求保存下一轮草稿并明确本轮不变，不为每句进度问题开一次付费AI调用。
5. 环境/登录/进程/解析异常显示三层说明与真实可用复查/仅验证入口；没有能力的按钮不显示。等待只是观察，暂停不提供，停止使用真实取消并等待终止确认。
6. Nova独立验证通过后显示已检查与未检查，不宣称完成。用户打开允许的本地产物或按明确路径手动查看；打开成功只说明系统已发出打开/加载成功，不能宣称已查看或验收。
7. 用户看完点击“我已查看，确认本轮完成”，复用accept_task_result和后端预检；只有返回completed才显示本轮完成。新调整生成下一轮未确认草稿，原证据与用户接受记录保留。
8. 细节抽屉随时可查四项原需求、采用/历史证据、真实命令与脱敏输出、七文档及重新生成；不必打开抽屉才能走完顺畅路径。

## 7. 必须保留的门禁与故障边界

- 用户需求轮与执行round明确分开：用户新轮对应独立确认草稿/Task；执行round1首次开发，round2仅一次自动返修；任务generation代表结果代际，不用UI轮号替换它。
- 四字段原文保留顺序、重复和换行；展示不重新规范化。既有确认项快照的内部切分规则保持，不用翻译/重写改变自查匹配；历史/终态不补造新快照。
- 确认版本、动作身份和服务端CAS为真门禁；历史卡按钮失效只作辅助。成功动作不重做，uncertain先核对。仅验证恢复在所有失败分支AI调用0，不为UI方便改普通恢复路径。
- Nova事实验证的task/project/generation/round/dev_attempt相容性、自查完成/覆盖/无阻断、测试构建真实通过/精确不适用依据、当前结果用户接受均不降低。文档只重生摘要，不制造证据。
- 修复只针对本范围可安全修复的代码断言失败；基础设施/登录/解析/进程启动错误不返修；恢复、切页、新卡不重置机会。新增需求不能在后台无限自动开新Task绕过上限。
- “通过验收”必须用户明确点击且后端成功；预览回执/AI自述/exit0不能自动验收。运行取消不删除用户改动或回滚项目；不能把已发送取消请求显示为已停。

## 8. 布局、持续反馈、错误恢复与双语验收标准

- 左230/48、右286/48、中区至少480；右抽屉默认收起，窄窗展开右侧则左侧让位、关闭恢复项目偏好。每区独立滚动、输入固定、长路径/输出折行；历史滚动距底≤80px贴底，上翻不抢位置，提供回到最新；卡片计时更新不滚动。
- 目标1024×700、1366×768、1600×900、最大化和Windows100%/125%/150%，中英长文案均验证；当前正式最小920×640须PM决定提升最小值还是继续兼容，不能只改CSS假装窗口配置已一致。若提升需单独列入审查的Tauri配置差异，保持CSP与生产bundle设置。
- B绿主方案+A暖纸同流程token；主操作44px、其他32px、键盘全可达、焦点2px/偏移2px、状态图标+文字。对比度≥4.5:1优先于照抄绿色白字/弱灰，必要调整文字色且记录，不复制第三方专有图标。
- 输入1–6行自动增高，Enter/Shift+Enter/IME正确；忙碌时可继续编辑和记录下一轮，但执行提交串行且幂等。拒绝/失败保留精确输入，异步完成不清除新输入。
- 记录阶段、最后真实事件时间、最后成功读取时间、最近存活核对时间必须分开。耗时来自真实动作开始/结束与可确认区间；崩溃/重启缺区间注明未知，不把等待时长当活动时间。

- 错误说明“发生什么→修改/记录已知影响→下一步”，未知保留未知；刷新失败主动可见，不继续暗示运行。重连只恢复观察，重复动作必须另有明确授权及资格；不修改全局CLI、认证、ACL、代理来“修好界面”。
- 所有新文案中英键齐全，运行期切换不重启、不清草稿、不改变执行，原始证据不机器改写；数字/时间本地化，错误码映射用户语言、脱敏原文可查。屏幕阅读器播报阶段/受阻/验证变化，不每秒播报时间；减少动画取消循环/位移。
